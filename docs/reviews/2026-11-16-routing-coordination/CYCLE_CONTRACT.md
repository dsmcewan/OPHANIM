# Standing priority: evaluate routing and coordination practices every cycle

Owner direction, November 16, 2026: review model routing, escalation and coordination; determining effective practices is a priority and must continue as part of the operating cycle.

This document makes that requirement concrete. It is an implementation/acceptance contract, not a claim that the current runner enforces it. Reuse Pantheon's authoritative blackboard, dependency coordination, chair boundaries, ledgers, contribution projections and retained investigation history. GitHub remains the published view of their records.

## Required cycle

1. **Open with the effective policy.** Name the routing and coordination policy version, scope, task class, provider/transport capabilities, resource limits, prior learning decision and unresolved practice questions. Restore the evidence needed for this task; do not replay an entire conversation as a coordination brief.
2. **Assess practices as a priority.** Review the previous cycle's accepted results, failures, retries, context duplication, waits, handoffs and resource use. Select the most useful unresolved question whose dependencies are ready. If telemetry is absent, instrumentation is the first concrete improvement task. Avoid perpetual debate while ready work exists.
3. **Choose a bounded next step.** Record one of `retain`, `insufficient_evidence`, `propose_measurement`, or `propose_policy`. Reuse a previous decision when its evidence and applicability are unchanged. A cycle need not buy a new experiment to record an honest assessment.
4. **Route and assign explicitly.** Admit context fit, role capability, independence and approved pool first. Then select the appropriate task band from eligible candidates using stated policy and measured evidence where available. Every default/pin needs a recorded reason. Retain full seat identity and pool across handoffs, retries and resume. Give each writer a precise file/obligation boundary and dependency versions.
5. **Evaluate → fix → test → independent review.** The controller checks actual bytes and executed acceptance. Distinct transports do not establish distinct model labs. Keep repair, output expansion, effort increases, model changes, quota waits and terminal stops as separate bounded actions. A missing reviewer is resumed in the same cycle; already valid work is reused.
6. **Compare before adopting.** For a practice candidate, retain a matched baseline and candidate under the same task/quality requirements and declared resource bounds. Measure accepted-result quality, total provider usage/cost where known, elapsed time, rework, retry/fallback calls and coordination overhead. Include failed/inconclusive results. Unknown cost stays unknown. An allowance is not a token bill, and agreement is not correctness.
7. **Review the practice evidence.** An eligible independent reviewer checks scope, raw results, interpretation, side effects and whether the comparison answers the chosen question. Record `promote`, `retain`, or `reject` for a qualified candidate, with applicability, provenance, policy hash, rollback and re-evaluation conditions. Unmeasured judgment remains labeled provisional.
8. **Carry the decision forward.** Close only with a recorded practice assessment/disposition alongside the existing review/finding gates. The next cycle cites and actually loads the admitted policy version, or records why it retained the previous one. Publish the resulting status/evidence after signed state changes.

The priority applies at every boundary. Actionable learning work belongs in the existing dependency queue; a genuine external hold is recorded while other Ready work continues. This is not permission for an unbounded background discussion or a new provider-spend allocation.

## Minimum acceptance cases

- Easy and hard tickets exercise the real dispatcher and demonstrate their intended model fit, or a recorded justified override; testing only the selector is insufficient.
- The same model served through two transports cannot fill two independent exploration/judge labs.
- A missing/failed reviewer can be retried in the existing cycle without rerunning valid responses.
- After a terminal stop there are zero further generation attempts for that stopped slot.
- Per-slot vendor/model/pool and resume identity reach the actual provider request unchanged unless a recorded decision authorizes a change.
- A 4,000-token explicit cap stays 4,000 on every eligible provider path; context reservation uses the effective cap.
- A failed/retried request contributes to attempt counts and resource evidence; missing usage/cost is unknown rather than zero.
- A cycle cannot close under the new contract without its assessment/disposition, including an explicit insufficient-evidence outcome when appropriate.
- The next actual dispatch cites/loads the retained or newly admitted practice policy; changing a document alone fails this test.
- A synthetic matched comparison verifies the mechanics; a scoped live comparison is needed before claiming measured provider cost/quality improvement.

## Implementation order

1. Repair terminal stops, override/pool preservation, explicit-cap propagation, lane pins, lab identity and review recovery. Wire task-fit selection into actual dispatch and make context admission consistent.
2. Retain per-attempt usage, effective settings, selection/exclusion reasons, latency and acceptance/review outcomes; separate provider accounting from publication bookkeeping.
3. Connect existing contribution/investigation tools to a new versioned practice-assessment/disposition record, cycle close requirement and next-dispatch consumption check. Preserve historical hashes and existing qualification rules.
4. Run guarded fake-provider integration cases across the complete cycle. Independently review the implementation and evidence.
5. Use an explicitly bounded live comparison when credentials and budget are available. Adopt only an independently qualified scoped policy; otherwise retain the named provisional one and its next measurement task.

The user's direction establishes this continuing priority. It does not settle K6, change pinned TELOS authority, authorize new credentials/spend, weaken review/acceptance, or let a learning component sign its own policy promotion.

# Bounded self-evaluation: the owner's conditions

Owner direction, 2026-11-17: "I'm approving the development of bounded self-evaluation, not automatic adoption of a new routing policy." The objective "is not to produce more tests, reports, rules, or model calls. It's to establish which practices work, why they work, and when they should change." And: "Do not declare the self-improvement mechanism successful until it demonstrates that it can detect and correct a previously observed class of failure without requiring me to point it out again."

This file records the eight conditions and, for each, what in the repository serves it today or what is still missing. It is a map, not a claim of compliance. The control contract (`docs/reviews/2026-11-16-workflow-handoffs/CONTROL_CONTRACT.md`) and the cycle contract (`docs/reviews/2026-11-16-routing-coordination/CYCLE_CONTRACT.md`) remain the governing requirements.

| # | Condition (owner's words, shortened) | Where it is served now | Gap |
|---|---|---|---|
| 1 | Establish what improvement means before testing it: intended outcome, reliability, context and compute, cost, and the owner's corrective intervention. Passing tests that don't establish the objective is insufficient. | Per-run metrics (`pantheon/src/practice/metrics.mjs`): accepted, first-pass, rework, provider calls and tokens per accept (unknown stays unknown), elapsed, escalations, coordination overhead. Owner intervention: `ophanim/lessons/corrections.json`. | Intervention is recorded per correction, not per run or cycle, so it is not yet in the per-cycle assessment. Since the owner's ruling of 2026-11-20 the registry keeps three things apart: who discovered an instance (the owner, an independent review, or another check, with the class's own registered check marked as such), who repaired it, and which reusable check was seen to catch it again. What a review found is reported as evidence that the review worked. Success is counted only when a class's own registered check detected a class the owner had already raised and the mechanism corrected it: no class has that yet. | Four classes have no executable detector. |
| 8 | Measure whether the owner's intervention is decreasing. | `node ophanim/lessons/corrections.mjs` reports owner interventions by date. | So far it is not decreasing: 3 on 2026-11-16, 9 on 2026-11-17. |

**Success criterion.** `corrections.mjs` reports success only when a class the owner raised is later both detected and corrected by the mechanism, with no owner involvement. Today: not demonstrated. The one detection so far (machine paths in a new review record, caught by CI) was corrected by the owner, so it does not count. This is not staged: a demonstration has to come from a real recurrence.
